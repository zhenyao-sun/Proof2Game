# Manuscript and source intake

Use this reference for guided startup, for a missing source during validation, or when the user requests `paper_ingest`. The command examples use `$SKILL` for the loaded Proof2Game skill directory and `$PROJECT` for the user's existing mathematics project folder. They require macOS or Linux, Python 3.11 or later, Git, and Poppler (`pdfinfo` and `pdftoppm`) for PDF input. Paths in requests are passed as JSON strings. The final argument can be `-` to read the request from standard input.

## Select the mathematics project and exact original

1. Use the project folder and input the user already provided. Ask for whichever is missing. If there is no manuscript yet, explain that Proof2Game starts from an existing math note or manuscript and can use a draft. Accept LaTeX, Markdown, PDF, or an arXiv link. A separate `paper_ingest` request needs the project folder and reference identity, without a target manuscript.
2. For a managed script task, establish whether the user wants to work on their unpublished mathematics or a public manuscript. Use an affirmative choice already given. Ask if the choice is materially unclear. Preserve the type and chosen target version in the task record. Before creating the first task or reference, run `python3 "$SKILL/scripts/intake.py" "$PROJECT" init-git`. This keeps an existing Git repository and creates a local one where needed. Keep research checkpoints on the user's working branch, using narrow paths.
3. Use the target file or link selected by the user. For an arXiv link, `arxiv-link URL` distinguishes an explicitly pinned version from a latest-version link. Read the official submission history and identify exactly which version the link resolves to. Download the exact PDF using its pinned version URL and verify the version/date evidence. A link pinned to v1 uses v1 even if newer versions exist. On resumption use the version in the task record. For other public targets verify the public date of the actual edition, including an applicable online-first date. Use original authority for these checks. Record evidence such as the history/publisher URL, date, and inspected version. If the version/date cannot be determined, save the state and resolve the gap before public validation.
4. Run `init-target request.json`. For unpublished work pass `{"input":"/path/to/notes.tex","project_type":"unpublished"}`. For public work also pass `version`, `public_date` in YYYY-MM-DD, `source_url` for the verified version, and `publication_evidence` with the checked location and facts. For arXiv add `arxiv_link` containing the original link and put the pinned arXiv URL in `source_url`. The script preserves the target bytes and reports the absolute `directory` with `target.json`. New targets are stored in `.proof2game/<id>/`. Existing `.mathgrove/<id>/` targets keep their original paths, receipts, and checkpoints. `target-status <id>` reads the original binding in either directory. If both directories contain the same ID, preserve both and establish which is authoritative before continuing. A new original version has its own folder, game script, state, checkpoints, and deliveries.
5. For PDF targets finish the page-image workflow below before drafting. For text inputs use the preserved original and respect any original local TeX includes and resources. Preserve relevant original sources/resources needed to understand or rebuild the input as provided. Put the English script and its resources beside `target.json`, separate from the preserved original. Use `proof_source_path` when it becomes available. Leave the original language and content intact. Determine main results directly from the manuscript unless the ambiguity would change which theorems are delivered. See [manuscript.md](manuscript.md).

## Acquire and select a reference

Search the project's `references/` first. `list-references` inventories registered versions and PDF filenames in the current project. Inspect that inventory as coordinator, and keep it out of workers' pre-source contexts. Unregistered local PDFs may be the intended original. Verify their exact version and discoverability before registration. Search online only when the needed reference/version is missing locally or when checking whether a local preprint has an eligible formal version. Search official or primary version records, use legal access, and keep dated evidence. A search fragment or model memory can give a lead. Cite and use a work only after reading the actual original.

For validation of a public target, filter every candidate by the date of that exact target version before considering formal publication preference. Exclude references or results, proof methods, additions, and corrections that only appeared after the cutoff. This applies to search findings, local holdings, and all validation worker payloads. For a reference whose publisher documents only a month or year, record that precision as `YYYY-MM` or `YYYY`. The whole documented period must be at or before the exact target cutoff to establish eligibility. If the period crosses the cutoff, seek a more precise date before relying on that version. A preprint eligible at the cutoff can be used when the formal version was only released later. Inspect the eligible version to verify that it already contains the invoked result. For unpublished work there is no project cutoff. External mathematical proof sources still need verifiably public versions. For references, prefer the eligible formal version, including online-first. If the user explicitly chooses an eligible preprint for a reference, use that edition. This preference applies to dependent references. The original manuscript still follows the user's own selection.

The deterministic helpers take the coordinator's findings and return next actions.

- `select-source` accepts `work_key` (stable identifier), `task_id` when bound to a target, optional boolean `required`, and `preferred_version` for an explicitly requested version or exact prior decision. Use `for_use: false` for standalone ingestion. `check_publication` means some facts needed to select remain unresolved. `choose_version` means inspect the candidate versions before selecting one. `need_pdf` identifies a missing eligible edition. `check_result` calls for inspecting the relevant pages of the actual reference PDF. With the exact hash and located result, repeat with `result_evidence: {"sha256":"...","locator":"Theorem 2.1, physical PDF page 8"}`. Use `ready` only after the requested verification has been carried out. `no_eligible_version` means none in the reviewed record fits the cutoff or chosen version.
- `record-publication` accepts `work_key`, `task_id` when applicable, `status` (`checked` or `unresolved`), `checked_at`, `evidence`, and a `candidates` array. Each candidate has `title`, `authors` (an array of names), `edition` (`published` or `preprint`), `version`, `public_date`, `source_url`, and `publication_evidence`. A `checked` record reports the evidence as of that date, including when no qualifying formal version was found. Reuse a valid record until a new publication lead or user request warrants another check.
- After obtaining the PDF, `register-reference` takes the same candidate fields plus `work_key` and `pdf` (path to the original bytes). It can also take a distinct `citation_key` and `id`. This makes a durable copy under `references/<id>/original.pdf`; `source.json` identifies the exact version and SHA-256. `reference-status <id>` returns that binding. Existing optional transcriptions are retained. Keep different versions separately; do not overwrite a version. Register the public target as a reference only when the verified derivation actually cites it or when the user independently requests it. For that exact target PDF, set `reuse_target` to the target ID to reuse its completed OCR.
- At the source gate or before supplying a selected source to another role, read the original result and its exact statement, assumptions, scope, and use in the proof. For a binding used at handoff, `verify-citations` takes `{"task_id":"...","sources":[{"id":"...","sha256":"...","citation_key":"key","cited_locations_physical_pages":{"Theorem 2.1":[8]}}]}`. The key may be omitted to use the registered key. Use an empty sources list when none are used. It checks the stored version/date, source digest and physical page bounds, and returns absolute PDF paths for downstream packaging. Save its result outside the public package and supply only verified sources and relevant pages to the current role. A binding records accountable inspection by the mathematical role. The utility checks bookkeeping.

### Missing PDFs

Try to get the exact eligible source first. If the necessary PDF or the PDF for a concrete optional reuse opportunity is still unavailable, save the affected step and ask the user to supply it. Let all review work that can run finish, batch the accepted findings, and hold at the Fixer stage while the source is missing. Resume the waiting gate after registration and inspection of the relevant pages of the supplied PDF. For an inaccessible eligible published version, follow this wait path unless the user explicitly chooses an eligible preprint.

If the user confirms that a PDF cannot be obtained, keep the proofreader source wait and the Fixer hold in place. When the user explicitly selects an eligible alternative edition, verify the cited result in that edition and use the [source resolution operation](state.md#action-receipts) with the user-confirmed version. An explicit waiver of optional reuse allows the waiting gate to continue without that opportunity. Where the request is handled before worker dispatch, `record-unavailable` supports a task-local acquisition record with `task_id`, `work_key`, `required`, `reason`, `resolution` (`unobtainable` or `waived_optional`), and the exact `version` when known. Use the verification ledger for round state and verdicts.

## Page-image OCR

Use the actual rendered page image for target manuscript PDFs, even when the PDF has a complete text layer. References can be registered, cited, or delivered from the exact original PDF and relevant-page evidence. Have the coordinator or a Codex worker view each image, transcribe it as faithful Markdown, and consult the original whenever uncertain. Text extraction can help cross-check. Keep physical page numbers, mathematical symbols, formulas and subscripts, reading order, statements, proofs, citations, figures and tables. Mark uncertain text, and do not silently fix a false result, infer missing expressions, or summarize. A confirmed blank page can be transcribed as `[Blank page]`.

For each missing or changed physical page of the target manuscript:

1. `render-page` takes `{"kind":"target","id":"...","page":1}`. Open the returned `image_path` using a local image inspection tool. Supply `dpi` to get a higher-resolution image for hard-to-read material.
2. Pass the same identifiers and any custom `dpi` to `record-page` along with the returned `image_sha256`, `reviewer` (actual responsible session), `method: "codex_pdf_image_ocr"`, `markdown`, and `uncertainties` (an array, possibly empty). A correction uses `replace_sha256` from the previous page record, preserving its history.
3. Run `finish-ocr` with `{"kind":"target","id":"..."}` when every physical page has an image-bound record. The checked Markdown is `original.md`. Use `target-status` to resume only pending pages. Checkpoint the source metadata, preserved PDF, Markdown, and page records rather than transient rendered PNGs.

## Standalone `paper_ingest`

Acquire and register the one reference selected by the user. Reuse an exact saved version when available. Report the preserved original PDF path and exact version. When invoked to resolve an existing verification wait, inspect the relevant pages and return to that wait point with the acquired evidence. Standalone ingestion ends when the selected reference PDF is preserved and registered.
