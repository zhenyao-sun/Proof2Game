# Automated script verification

The main session owns the verification, worker dispatch and continuation. This reference also governs manual `refactor`. The internal Proofreader, its loop, Explorer, route evaluation and automated refactor are stages of verification. Use [workers.md](workers.md) for mathematical responsibilities and role defaults, and [state.md](state.md) for the single project ledger, its command interface, and immutable result bindings.

## Start and resume

Use the recorded project type, original version and cutoff. Establish the user's authorized scope from the current task and the actual saved checkpoint. Confirm the script's structure and preserve valid saved work. A new guided script begins with every Main Results component in scope and unsafe unless there is already valid review evidence for it. For an existing script without valid review state, check its structure and existing evidence before initializing. Invalidate work whose bindings no longer hold.

Use the project ledger for the task objective and completion criteria. Guided verification continues through every applicable checked delivery or the authorized withdrawal outcome. Standalone verification completes after the current proof obligations close and the same script revision passes mathematical review and the applicable final route assessment. Follow [startup.md](startup.md) for optional host Goal tracking.

When resuming, match the actual script and resources, ledger revision, current scope, worker session and current assignment. Retain still-valid completed verdicts and cumulative counts. A saved session identity alone cannot confirm host recovery. Replace lost workers by the rules in [workers.md](workers.md). Continue from an intake or refactor decision as soon as its prerequisites arrive. The main agent coordinates continuously without a supervisor or periodic approval. Pause at a concrete issue that needs user input, a real host capability gap, or a user-requested pause. A persistent cycle may warrant refactor when there is mathematical evidence of no progress and a real user decision is needed. There is no fixed review, loop or exploration cap.

## Review and explore

`M` is the set of canonical components in `main.tex`. `U` is the union of the disjoint `safe` and `unsafe` sets. `C` is the actual dependency union rooted at **every** current target, including requisite Statements, Proofs, and effective Conventions. Determine dependencies from the assembled script and actual argument; structural and reference checks support this judgment. Review state is specific to a version, context and dependency interfaces. Explore has authority to reconcile `U` after initialization. There are no user commands to add, remove, or mark components. An applicable updater may remove deleted identities and invalidate existing entries as detailed below.

1. **Choose work.** Begin with the Main Results batch. Thereafter, at each round boundary compute `C` afresh. When `C ∩ unsafe` is nonempty, start or continue the proofreader loop. Enqueue only that intersection for the next round. When it is empty, proceed directly to Explorer and skip an empty round or loop. An out-of-cone unsafe entry does not block this transition.
2. **Review independently.** Bind the round to the exact current draft and resources, and each worker assignment to a component and gate. Dispatch the progressive gates in [workers.md](workers.md). Reconcile every accepted result against its live binding. Discard stale results from the current decision while preserving history. A source wait frees a running Reviewer slot. Once all review work that can run has returned, hand the Batcher the accepted findings and identify the pending source waits separately.
3. **Fix and update.** Transfer all findings once, losslessly, through a fresh Batcher to one serial Fixer, and track a disposition for every finding. If a mathematical repair cannot be found or target meaning must change, send the actual issue through `refactor`. Keep the same interrupted round. On a complete round apply only its Proofreader Updater and count it once. Compute `C` again against the applied script. Continue the same loop until the intersection is empty, then record the completed loop. At the end of a round report findings, repairs, unresolved issues, changed components and the full safe/unsafe lists. At loop completion report its reason, rounds, major changes and lists. Report and continue automatically.
4. **Explore the whole dependency union.** With `C ∩ unsafe` empty, run a fresh Explorer following [workers.md](workers.md). Remove from `U` those now outside `C`, retaining their source and historical verdicts. Admit all existing missing members of `C` together, including all shared obligations once. Keep still-valid in-range reviews and set every added or readmitted identity to unsafe. Try interface improvements only for proposed new or returning members. When edits are applied, use the Interface Optimizer Updater to invalidate affected prior reviews, then compute final additions/removals against the new script. Components may return from discarded branches when their use is valid. Exploratory admission itself does not create new components.
5. **Re-evaluate.** If the new `C ∩ unsafe` is nonempty, start a new loop. Once all of `C` is in range and safe, actively verify that all target proof obligations are in fact closed and that Explorer has no remaining work. Structural checks, absence of a placeholder, or compilation alone cannot certify mathematical closure. If a concrete unresolved obligation remains, return it to the applicable review or refactor path. Enter the final route assessment with a current, fully bound script only after closure. Report the stopping reason, completed outer loop count, principal mathematical changes, full classification lists and final Explorer result.

### Source waits

In the sources gate, manuscript-local references use the supplied manuscript interfaces. Check original PDFs for concrete external dependencies. In the reuse gate, look up an original only for a concrete opportunity to replace a nontrivial repeated derivation or an identified attribution issue. A gate with no applicable external source passes with an empty external source list.

Use the local-first search, version selection, cutoff, and verification evidence rules in [intake.md](intake.md). If an exact PDF is unavailable for a required interface or a specific optional reuse opportunity, record the waiting role, current step and specific mathematical use, then ask the user for the PDF. Other active Reviewers may progress. A serial worker waits at the current step. Retain current assignments and counts while waiting. Once the original is obtained and ingested, automatically continue the waiting step with eligible evidence.

After the Batcher returns, hold at the Fixer stage while any Reviewer source remains unresolved. Keep the draft, findings, classifications and outstanding review assignments intact. The Fixer starts or resumes work only after its source waits have cleared and all pending Reviewer gates have completed. A report that a PDF is unobtainable leaves the wait in place. An explicit waiver can clear an optional opportunity. Record the waiver and reuse it while that source remains optional. Resume each waiting Reviewer gate with verified material as it arrives. If a resumed review adds findings, update the Batcher handoff to include all findings before starting Fixer work.

## Candidate changes and classification

Prepare changes in isolation. Record the precise starting version, stable component identities, exact staged changes, purpose, and mathematical impact on the component, its direct consumers, conventions, and paired Statement. Have the applicable role determine whether interfaces, responsibilities or content changed substantively, with reasons. A meaning-preserving edit can be made after a nonpass and does not cure that verdict. Hashes bind content; they do not determine mathematical meaning. Before applying, check the live starting binding, validate structure, pairing, dependencies, references and continuity, and actually compile changed TeX. Keep recoverable state if applying fails, and retry without duplicating effects or counters.

For every provenance of change, a move that substantively alters how a Statement follows the surrounding preceding text invalidates the affected Statement. Look at the moved Statement and other affected neighbors. A pure move or rename otherwise retains identity. When splitting, only a still-present modified original can inherit the original identity; new pieces wait for Explorer. For merges, use the actual create, delete, move and edit operations. Deleted components exit `M` and `U`.

- **Proofreader Updater.** In the remaining old `U`, the item must be either previously safe or a previously unsafe item whose own current round passed every gate. Additionally, it must have no substantive edit to itself, substantive change to its direct Statement interfaces, substantive change to its full ambient convention stack, or, for a Proof, substantive change to the paired Statement interface. Items failing any condition, including continuity, stay or become unsafe. A Fixer repair of a nonpass leaves the item unsafe for a fresh Reviewer next round.
- **Refactor Updater.** Outside an active Proofreader round, preserve current safe only under the same no-change conditions. Keep existing unsafe entries unsafe. New and previously out-of-range members await the Explorer. When refactor happens inside an active round, use the Proofreader Updater once for the combined round.
- **Interface Optimizer Updater.** Apply the same invalidation as for an out-of-round refactor to the already classified items when Explorer applied actual edits. Then use the current script and the Explorer's whole-cone reconciliation to remove or admit components. It cannot promote unsafe to safe.

Prevent unauthorized changes to a target's mathematical meaning, including via changes to a hypothesis, conclusion, definition or convention, and including withdrawal. Auxiliary components may change with the authorized research. A necessary target change must go to `refactor` with the exact proposed change, reason and impact for explicit user confirmation.

## Final route assessment

Bind each assessment to the same script and resource version as the successful mathematical review. Before each internal refactor, save a named local Git checkpoint containing that route and its recoverable research state. Keep findings, counters, attempts and comparisons when rolling back. Restore the applicable workflow-managed draft and matching effective review state. Preserve unrelated user work, original input, and history rather than resetting an entire checkout.

### Own unpublished mathematics

Ask a fresh independent simplification reviewer to examine the complete working draft and recorded attempts. Authorized proof exploration permits alternate approaches, eligible public sources and discarded branches. The criterion is a feasible reduction in actual mathematical proof burden. If a substantive simplification exists, automatically carry it into a fresh Refactor implementation and run the relevant updater, Explorer and math review again. A real target change still needs user confirmation.

After the candidate is complete and independently re-reviewed, compare actual proofs against the checkpoint. Keep a clearly simpler route. If implementation was proved infeasible or the completed original is simpler, restore the checkpoint, retain the evidence and start a fresh route assessment knowing the failed attempt. Ordinary repairable nonpasses go through the normal Fixer. If both proved routes have genuine tradeoffs with no clear winner, the main session can choose either and record the reason. Record the original, candidate, implementation, math review, actual complexity comparison and disposition so later sessions do not repeat a failed or reversed comparison. Continue until the current version has an independent finding of no feasible further substantive simplification.

### Public-literature project

The independent route reviewer reads the exact original edition and current draft. It judges whether the current core reasoning is traceable to the original, allowing equivalent expressions, reordering and completion of omitted steps. Ordinary Reviewer findings remain independent. Other eligible literature covering part of the argument is not by itself a route defect. A genuine route nonpass triggers internal refactor, using the concrete discrepancy to restore the original route where sound. Preserve failed attempts and recover the prior checkpoint if a proposed route is infeasible. Repeat independent mathematical review of affected work and then use a fresh route reviewer for the same resulting version. Both must pass together.

For a verified hard error in the target, maintain project `report.md` with exact version, original page and formula or paragraph, the mathematical problem and checked evidence, impact on target conclusions, and status. Record which step must change, why a detour is necessary, and the actual replacement proof when applicable. A necessary detour needs the ordinary independent math review and a fresh final route review that tests both the source defect and necessity of the departure. If Fixer cannot reliably repair a core error, preserve the defect and failed reasoning, pause into `refactor`, and explain the decision needed. For a counterexample, Fixer shows the user the witness and checks it against the original hypotheses and the exact contradicted conclusion. This user consultation uses Fixer's verified evidence directly.

When the user confirms a mathematically revised target, record original conclusion, checked counterexample, consent and revised conclusion. Re-admit and re-review affected components, get same-version route acceptance including the authorized change, and proceed to applicable delivery. When the last target is withdrawn with confirmation, keep the underlying evidence and decision. In guided mode the public task now delivers only the checked referee report under [writer.md](writer.md). An own unpublished task saves current work, explains the reason and ends at that explanation.

## Refactor discussion and recovery

For a manual refactor or a real blocker, the main agent explains the precise problem and supporting evidence. Discuss one material question at a time. Reconcile corrections and test proposals in side drafts. The formal script stays fixed while agreement is unsettled. Once agreed, summarize the decision, take explicit target-change authorization when needed, and have a fresh implementation worker execute the agreed path. Acquisition alone resumes the waiting task. A no-action decision preserves a recoverable pause until the user expressly supersedes it. If the agreed change proves infeasible or requires a new decision, return to the same discussion with the evidence and staged work intact.

When the discussion belongs to an active round, combine approved edits with existing Fixer changes and return to that round. Without an active round, apply only the Refactor Updater and resume the parent verification where applicable. A standalone `refactor` ends after its agreed implementation and update without separately initiating review or exploration. If the user expressly abandons unfinished verification and requests standalone refactor, change mode at a stable boundary with no pending write transaction, preserving the old records and counts. An agreed no-action pause needs explicit supersession and the same safe boundary before a new operation.

## Snapshot and delivery incidents

After both reviews pass, produce one compile-ready handoff snapshot retaining exactly the active targets and their dependencies, with numbering, pairings, references and resources checked on the retained structure. Keep discarded work and its history in the working project. Give both production roles that immutable snapshot. For the public referee report, also give Writer the preserved original and any independently checked original errors, including findings on discarded branches. Guided delivery schedules the game and either the public referee report or the unpublished paper, potentially in parallel, and hands over each when it passes its own checks. Independent output issues affect only their own delivery. Standalone validation stops after the same-version verification endpoint.

Game and Writer work inspect fidelity to the validated English script and their own deliverables. If one incidentally uncovers a substantive mathematical error in the shared script, record the exact location, evidence, impact and snapshot. Suspend every delivery relying on that snapshot, notify the user about any affected version already delivered, and return the shared problem to core validation. After mathematical and applicable same-version route review, generate replacements from one new snapshot. If only the translation or ordinary rewrite is wrong, have its production worker fix and check that output. When a suspected erroneous counterexample would invalidate the basis for a public detour, return the counterexample and route together for fresh evaluation. If rechecking evidence for withdrawal shows the counterexample fails and there is no other verified basis, return to refactor with the specific defect. The user chooses to restore verification or maintain withdrawal.
